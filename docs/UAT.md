### Result key

- **Pass:** expected behavior reproduced on the target device and evidence recorded.
- **Fail:** behavior contradicts the expected result; create a defect with reproduction steps.
- **Partial:** some expected behavior is verified, but one or more required substeps remain open; do not count it as accepted.
- **N/A:** feature is formally excluded from this product build, with the product owner’s rationale recorded.
- **Not run:** no evidence yet.

For every case, record `Result: Not run / Pass / Partial / Fail / Blocked / N/A` and an evidence or defect ID. ADB-injected keys, emulator tests, and screenshots can support diagnosis, but do not count as physical-controller acceptance.

## Safety and test data

- Use only homebrew, freeware, open-source, or game copies the tester is authorized to use. Never download or distribute commercial ROMs, ISOs, BIOS, keys, firmware, or copyrighted game binaries for this UAT.
- Use a disposable test profile, test catalog, test save, test WebDAV/S3 endpoint, and non-production Windows library where possible. Do not use real cloud-save credentials in screenshots or logs.
- Perform destructive tests only on named test titles and disposable files. Verify the target path before deleting anything.
- Pairing, credential revocation, app uninstall, content removal, and external-storage migration affect persistent state; record the intended test account/device and recovery path first.
- Do not run Android instrumentation on the HONOR. Use local unit tests/build checks and manual, display-targeted acceptance steps.
